Core Problem

The Need for Version Control

Without version control, team collaboration quickly degrades into confusing file duplication.

  • Manual ZIP file management leads to lost code and overwritten changes (e.g. project_v2_final.zip).
  • No clear audit trail of who made a change, when it occurred, or why it was done.
  • Git Solution: Every modification is tracked as a clean, immutable snapshot in a central timeline.
Mental Model

The 3 Local Git Areas

Understanding how Git organizes file states locally before sending them to GitHub.

  • 1. Working Directory: The actual files on your computer where you write code.
  • 2. Staging Area: The staging area (Index) where files are prepared using git add.
  • 3. Local Repository: Permanent snapshot history saved via git commit.
Execution Flow:
Working Directory
    ↓ git add
Staging Area
    ↓ git commit
Local Repository
    ↓ git push
GitHub (Remote)
Step 1: Setup

Environment Check & User Identity

Configure your Git name and email to ensure your commits are properly authored.

git --version
git config --global user.name "Your Full Name"
git config --global user.email "your.email@example.com"
Step 2: Clone

Clone the Workshop Repository

Download a full local copy of the project repository to your laptop.

git clone https://github.com/your-username/git-ready.git
cd git-ready
Open index.html in your browser to view the initial Wall of Fame before making changes.
Step 3: Inspect

Repository Compass: git status

Run git status whenever you want to check your active branch and untracked files.

git status
# Output: On branch main, your branch is up to date with 'origin/main'.
Step 4: Branching

Create a Feature Branch

Isolate your individual work from the primary main branch.

git checkout -b student/your-github-username

The -b flag tells Git to create a new branch and immediately switch your workspace to it.

Step 5: Hands-On

Create Your Student Profile JSON

In your editor, add a new JSON file under data/students/your-github-username.json.

{
  "id": "your-github-username",
  "name": "Your Name",
  "role": "Student / Learner",
  "bio": "Learning Git and web development hands-on!",
  "techStack": ["JavaScript", "HTML", "Git"],
  "github": "your-github-username",
  "cardColor": "#3b82f6",
  "quote": "Building software together."
}
Step 6: Stage

Stage Your Changes: git add

Move your new JSON profile file into the Staging Area.

git add data/students/your-github-username.json
# Or stage all changed files:
git add .
Running git status after staging will show your file listed under "Changes to be committed" in green.
Step 7: Commit

Create a Commit Snapshot

Record your staged modifications permanently in your local Git repository.

git commit -m "feat: add profile card for [Your Name]"
Step 8: Push

Push Branch to GitHub

Upload your feature branch to the remote GitHub server.

git push origin student/your-github-username
Step 9: Collaborate

Create a Pull Request (PR)

Submit your branch for review so it can be merged into the main codebase.

  • Open the repository on GitHub in your web browser.
  • Click the "Compare & pull request" button on your newly pushed branch.
  • Title your PR feat: add profile card for [Name] and click Create pull request.
Step 10: Review

Live PR Review & Merge

The workshop host will review all student Pull Requests on the projector screen and merge them into main.

Watch the screen as your Pull Request gets merged into the central repository!
Step 11: Sync

Sync Everyone's Profile Cards: git pull

Fetch all newly merged classmate profiles onto your computer.

git checkout main
git pull origin main
Refresh index.html in your browser to see all merged student cards render live!
Pro Tip

Handling Merge Conflicts

Conflicts occur when concurrent edits modify the exact same lines in a file.

<<<<<<< HEAD (Your current branch)
"role": "Frontend Learner"
=======
"role": "Fullstack Developer"
>>>>>>> main (Incoming branch)

Resolution: Choose the desired content, delete the marker lines (<<<<<<<, =======, >>>>>>>), then stage and commit.

Best Practices

Core Git Best Practices

  • Commit Frequently: Make small, focused commits for single logical changes.
  • Use Feature Branches: Keep the primary main branch clean and stable.
  • Descriptive Commit Messages: Explain the purpose of changes clearly.
Real World

Real-World Industry Application

How engineering teams rely on Git & GitHub daily for production software development.

  • Continuous Integration (CI): Automated testing runs on every Pull Request before code reaches production.
